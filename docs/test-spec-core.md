# ТЗ на тестирование ядра шахмат

## Цель

Проверить, что ядро шахматной игры корректно реализует правила шахмат, стабильно ведет состояние партии и предоставляет предсказуемый API для дальнейшей интеграции с приложением.

Область тестирования: интерфейс `IGameEngine` в `ChessGame.Core`.

## Объект тестирования

Методы `IGameEngine`:

- `GetCurrentTurn()`
- `GetBoard()`
- `GetHistory()`
- `GetPossibleMoves(ChessBoardCell cell)`
- `MakeMove(Move move)`
- `CancelMove()`
- `DownloadGame()`
- `SaveGame()`
- `GameOver()`
- `ExportState()`

## Формат тест-кейсов

Каждый тест-кейс должен содержать:

- **ID**
- **Название**
- **Приоритет** (`P0`, `P1`, `P2`)
- **Предусловия** (позиция, очередь, флаги, история)
- **Действия** (вызов метода)
- **Ожидаемый результат** (статус, состояние доски, очередь, история, экспорт)

## Приоритеты

- **P0**: критические правила, без которых игра работает неверно.
- **P1**: важные шахматные механики и спецправила.
- **P2**: расширенные и редкие сценарии, устойчивость и стресс.

## Группы тестов и кейсы

### 1. Инициализация и базовые инварианты

- `CORE-INIT-001` (P0): стартовая расстановка фигур соответствует правилам.
- `CORE-INIT-002` (P0): первый ход у белых (`GetCurrentTurn()`).
- `CORE-INIT-003` (P0): история в начале пустая.
- `CORE-INIT-004` (P1): `ExportState()` на старте отражает начальное состояние.
- `CORE-INIT-005` (P1): повторные вызовы `GetBoard()` и `GetHistory()` не изменяют состояние.

### 2. Валидация входных данных

- `CORE-VAL-001` (P0): `GetPossibleMoves()` для пустой клетки.
- `CORE-VAL-002` (P0): `MakeMove()` с ходом из пустой клетки.
- `CORE-VAL-003` (P0): `MakeMove()` фигурой не того цвета (не в свой ход).
- `CORE-VAL-004` (P0): ход в ту же клетку.
- `CORE-VAL-005` (P0): ход вне границ доски.
- `CORE-VAL-006` (P1): `MakeMove(null)` (если допустимо контрактом).
- `CORE-VAL-007` (P1): `CancelMove()` при пустой истории не приводит к аварии.

### 3. Ходы фигур: корректность и ограничения

#### Пешка

- `CORE-PAWN-001` (P0): ход на 1 клетку вперед.
- `CORE-PAWN-002` (P0): ход на 2 клетки с начальной позиции.
- `CORE-PAWN-003` (P0): запрет хода на 2 клетки не с начальной позиции.
- `CORE-PAWN-004` (P0): запрет хода вперед при блокировке.
- `CORE-PAWN-005` (P0): диагональное взятие.
- `CORE-PAWN-006` (P0): запрет взятия по прямой.
- `CORE-PAWN-007` (P0): запрет хода назад.

#### Конь

- `CORE-KNIGHT-001` (P0): валидные L-образные ходы.
- `CORE-KNIGHT-002` (P0): прыжок через фигуры.
- `CORE-KNIGHT-003` (P0): запрет не-L хода.

#### Слон

- `CORE-BISHOP-001` (P0): валидные диагональные ходы.
- `CORE-BISHOP-002` (P0): запрет хода через фигуры.
- `CORE-BISHOP-003` (P0): запрет недиагональных ходов.

#### Ладья

- `CORE-ROOK-001` (P0): валидные вертикальные/горизонтальные ходы.
- `CORE-ROOK-002` (P0): запрет хода через фигуры.
- `CORE-ROOK-003` (P0): запрет диагональных ходов.

#### Ферзь

- `CORE-QUEEN-001` (P0): валидные ходы как слон + ладья.
- `CORE-QUEEN-002` (P0): запрет хода через фигуры.

#### Король

- `CORE-KING-001` (P0): ход на одну клетку во всех направлениях.
- `CORE-KING-002` (P0): запрет хода под бой.
- `CORE-KING-003` (P0): запрет хода, оставляющего своего короля под шахом.

### 4. Спецправила

#### Рокировка

- `CORE-CASTLE-001` (P1): короткая рокировка при выполнении условий.
- `CORE-CASTLE-002` (P1): длинная рокировка при выполнении условий.
- `CORE-CASTLE-003` (P1): запрет рокировки, если король ходил.
- `CORE-CASTLE-004` (P1): запрет рокировки, если соответствующая ладья ходила.
- `CORE-CASTLE-005` (P1): запрет рокировки при фигурах между королем и ладьей.
- `CORE-CASTLE-006` (P1): запрет рокировки из-под шаха.
- `CORE-CASTLE-007` (P1): запрет рокировки через битое поле.
- `CORE-CASTLE-008` (P1): запрет рокировки в шах.

#### Взятие на проходе

- `CORE-ENPASSANT-001` (P1): допустимое взятие на проходе сразу после двойного хода пешки соперника.
- `CORE-ENPASSANT-002` (P1): запрет взятия на проходе, если пропущен один ход.

#### Превращение пешки

- `CORE-PROMO-001` (P1): превращение пешки на последней горизонтали.
- `CORE-PROMO-002` (P1): превращение с взятием.
- `CORE-PROMO-003` (P1): поддержка вариантов превращения (ферзь/ладья/слон/конь).

### 5. Шах, мат, пат

- `CORE-CHECK-001` (P0): фиксация шаха после хода.
- `CORE-CHECK-002` (P0): `GetPossibleMoves()` возвращает только ходы, снимающие шах.
- `CORE-CHECK-003` (P1): двойной шах ограничивает ответ только ходом короля.
- `CORE-MATE-001` (P0): корректное определение мата и завершение партии.
- `CORE-STALE-001` (P0): корректное определение пата.

### 6. Ничьи по правилам

- `CORE-DRAW-001` (P2): ничья по недостаточности материала `K vs K`.
- `CORE-DRAW-002` (P2): ничья по недостаточности материала `K+B vs K`.
- `CORE-DRAW-003` (P2): ничья по недостаточности материала `K+N vs K`.
- `CORE-DRAW-004` (P2): троекратное повторение позиции (если поддерживается).
- `CORE-DRAW-005` (P2): правило 50 ходов (если поддерживается).

### 7. Поведение `MakeMove()` и `MoveStatus`

- `CORE-STATUS-001` (P0): успешный обычный ход возвращает корректный статус.
- `CORE-STATUS-002` (P0): невалидный ход возвращает корректный статус ошибки.
- `CORE-STATUS-003` (P1): статус для шаха/мата/пата корректен.
- `CORE-STATUS-004` (P1): статус для спецходов (рокировка, en passant, promotion) корректен.
- `CORE-STATUS-005` (P0): после невалидного хода состояние доски и очередь не меняются.

### 8. История и отмена хода

- `CORE-HIST-001` (P0): после валидного хода история увеличивается на 1.
- `CORE-HIST-002` (P0): `CancelMove()` откатывает последний ход и очередь.
- `CORE-HIST-003` (P1): откат рокировки корректно возвращает короля и ладью.
- `CORE-HIST-004` (P1): откат взятия на проходе корректно восстанавливает пешку.
- `CORE-HIST-005` (P1): откат превращения возвращает пешку в исходное состояние.
- `CORE-HIST-006` (P1): последовательность из N ходов и N откатов возвращает стартовое состояние (по `ExportState()`).

### 9. `GetPossibleMoves()` как контракт

- `CORE-MOVES-001` (P0): список ходов не содержит нелегальных ходов.
- `CORE-MOVES-002` (P0): ходы, оставляющие своего короля под шахом, исключены.
- `CORE-MOVES-003` (P1): для связанной фигуры (pin) возвращаются только допустимые ходы.
- `CORE-MOVES-004` (P1): результат не содержит дубликатов.
- `CORE-MOVES-005` (P1): повторные вызовы без изменения состояния дают эквивалентный результат.

### 10. Сохранение, загрузка, экспорт

- `CORE-STATE-001` (P1): `SaveGame()` + `DownloadGame()` восстанавливают доску и очередь.
- `CORE-STATE-002` (P1): после загрузки корректно восстановлена история.
- `CORE-STATE-003` (P1): после загрузки сохранены права рокировки и en passant.
- `CORE-STATE-004` (P2): загрузка поврежденного состояния обрабатывается корректно.
- `CORE-STATE-005` (P1): `ExportState()` детерминирован для одинакового состояния.

### 11. Устойчивость и стресс

- `CORE-ROBUST-001` (P2): длинная серия валидных ходов не приводит к ошибкам выполнения.
- `CORE-ROBUST-002` (P2): чередование валидных и невалидных ходов не ломает состояние.
- `CORE-ROBUST-003` (P2): многократные `CancelMove()` после длинной партии корректно откатывают состояние.

## Критерии готовности тестового покрытия

- Все кейсы `P0` автоматизированы и проходят стабильно.
- Не менее 80% кейсов `P1` автоматизировано.
- Все реализованные в ядре правила шахмат покрыты позитивными и негативными сценариями.
- Для каждого публичного метода `IGameEngine` есть минимум один позитивный и один негативный тест.

## Примечания по реализации

- Использовать шаблон AAA (Arrange, Act, Assert).
- Для однотипных сценариев применять параметризованные тесты.
- Подготовить фабрику тестовых позиций для короткой записи предусловий.
- Фиксировать ожидаемые статусы `MoveStatus` отдельно, как контракт ядра.
- Если часть правил (например, 50 ходов/повторение) еще не реализована, кейсы помечать как `Planned` до реализации.
