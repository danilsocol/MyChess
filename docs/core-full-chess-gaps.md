# Анализ ChessGame.Core: что нужно для полноценных шахмат

Документ основан на просмотре текущего кода (`GameEngine`, `RulesValidator`, фигуры, `ChessBoard`, модели ходов). Ниже — **отсутствующие правила и возможности**, а также **известные дефекты реализации**, мешающие даже частичной корректности.

---

## 1. Критические дефекты в уже написанном коде

Эти пункты стоит исправить до расширения функциональности; иначе тесты и UI будут опираться на неверное поведение.

| Область | Проблема |
|--------|-----------|
| `OffsetChessFigure` (конь, король) | Своя фигура на клетке не отсекается — ход может попасть на занятую своим цветом клетку. Для взятия внутри блока всё ещё используется `cell.Color` (цвет **поля**), а не только цвет фигуры — часть взятий теряется или ошибочно разрешена. |
| `RulesValidator.IsCheckmate` | Логика возвращает `true`, если найден **хотя бы один** ход, снимающий шах. По правилам мат — это отсутствие таких ходов. Семантика метода **перевёрнута** относительно названия. |
| Рокировка в `MakeMove` | При выполнении хода **ладья не перемещается**, `MoveType` не обрабатывается — рокировка как единый ход не реализована. |

---

## 2. Обязательные правила FIDE, которых нет (или нет целиком)

### 2.1. Легальность хода и шах

- Нет фильтрации **псевдоходов** до **легальных**: нельзя оставлять своего короля под боем, нельзя ходить в шах (кроме кейсов с рокировкой после починки генерации).
- Нет фильтрации до **легальных** ходов (см. ниже); линейные фигуры при корректном скольжении по лучу всё равно должны проходить через этот слой.
- **Взятие на проходе** — не генерируется и не исполняется; нет состояния «пешка только что прошла на два» (целевая клетка для взятия).
- **Превращение пешки** — достижение последней горизонтали не меняет тип фигуры; `MoveType.Promotion` в перечислении не используется в движке; выбор ферзя/ладьи/слона/коня отсутствует.

### 2.2. Рокировка (полный набор условий)

В генерации ходов короля учтено отсутствие рокировки в шахе и проход через битые поля; остаётся доработать исполнение и откат:

Нужно явно:

- Король и соответствующая ладья **не ходили**.
- **Нет фигур между** королём и ладьёй.
- Король **не в шахе**, не проходит через **атакуемые** клетки, не попадает в шах **после** рокировки.
- При исполнении хода одновременно переместить короля и ладью; при отмене хода — корректно откатить обе.

### 2.3. Окончание партии

- **Мат** — должна совпадать семантика `IsCheckmate` с правилами и интеграция с `GameEngine` (остановка ходов, статус, при необходимости `MoveStatus.GameOver`).
- **Пат** — нет `IsStalemate` / логики «нет легальных ходов и нет шаха».
- **Ничьи по правилам** (минимально для «полноценной» партии часто требуют):
  - три кратного повторения позиции;
  - правило 50 ходов (без пешечного хода и без взятия);
  - соглашение о ничьей недостаточно материала (K vs K, K+N vs K, K+B vs K и т.д.) — по желанию уровня точности.

Сейчас `GameState` содержит флаги `IsCheck`, `IsCheckmate`, `IsStalemate`, но `ExportState` **всегда передаёт `false`** для этих полей — состояние конца игры не вычисляется и не хранится осмысленно.

### 2.4. Специальные случаи

- **Двойной шах / открытие линии** — после починки «легальности» проверяется через симуляцию хода (частично есть `WouldMoveRemoveCheck`, но нет единого «после хода король не под боем» для всех фигур).
- **Нельзя брать короля** — в шахматах короля «бьют» только косвенно (мат/пат); явной модели может не быть, но движок не должен позволять «взять короля» как обычную фигуру, если UI такое отправит.

## 3. API и инфраструктура

| Компонент | Состояние |
|-----------|-----------|
| `IGameEngine.SaveGame` / `DownloadGame` | `NotImplementedException` — нет сериализации/загрузки партии. |
| `IGameEngine.GameOver` | `NotImplementedException` — нет явного завершения и итогового результата. |
| `MoveType` | Значения есть, но комментарии в коде перепутаны (`Castling` помечен как «Шах», `Promotion` как «Свап»); **взятие на проходе** отдельного типа нет. |
| История | `HistoryMove` хранит взятую фигуру; для en passant и рокировки понадобятся дополнительные поля (взятая пешка не на клетке назначения, прежняя позиция ладьи и т.д.), иначе `CancelMove` будет некорректен. |
| Нотация / PGN | Не входит в Core, но для «полной» игры часто нужны экспорт/импорт ходов. |

## 4. Рекомендуемый порядок доработок ядра

1. Довести `OffsetChessFigure`: не ходить на клетку со **своей** фигурой; при взятии опираться только на `cell.Figure.Color`, без `ChessBoardCell.Color` (цвет клетки доски).
2. Ввести единый слой **легальных ходов** (фильтр псевдоходов через симуляцию + проверка шаха своему королю); использовать его в `GetPossibleMoves` / `MakeMove` / `RulesValidator`.
3. Починить `IsCheckmate` и добавить `IsStalemate`; обновить `ExportState` или убрать мёртвые флаги до реализации.
4. Реализовать рокировку в `MakeMove` и `CancelMove` (перемещение ладьи, при необходимости расширить `HistoryMove`).
5. Реализовать en passant (состояние после двойного шага пешки + ход + откат).
6. Реализовать превращение (тип фигуры в `Move` или отдельный параметр API).
7. По необходимости — повторы, 50 ходов, ничья по материалу; затем `SaveGame`/`DownloadGame` с учётом расширенного состояния.

---

## 5. Краткое резюме

Сейчас ядро — **заготовка**: есть доска, ход по псевдоправилам, отмена простого хода, частичная проверка шаха, скольжение линейных фигур и условия рокировки в генерации ходов короля. Для **полноценных шахмат по FIDE** по-прежнему не хватает доработки коня/короля в `OffsetChessFigure`, легальности ходов, исполнения рокировки в `MakeMove`, взятия на проходе, превращения, корректного мата/пата/ничьих, осмысленного `GameState`, а также сохранения/загрузки и завершения игры в `IGameEngine`. Критично устранить перечисленные в разделе 1 **дефекты**.
